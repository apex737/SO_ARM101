# PBL 템플릿 사용법

AI에게 구현을 맡기면서 진행·설정값·미이해·동작 구조를 남기는 프로젝트 템플릿입니다.
별도 플러그인, AI 전용 설정, 설치 프로그램은 필요 없습니다.

## 1. 시작 — 이것만 하면 됩니다

1. ZIP을 풀고, 나온 폴더를 프로젝트 안에 `PBL`이라는 이름으로 넣습니다.
   다른 이름을 쓰면 아래 문장의 경로만 바꿉니다.
2. AI가 이 폴더와 프로젝트 코드를 읽고 수정할 수 있게 합니다.
3. 아래 문장을 AI 대화창에 붙여넣습니다.
   경로와 만들 것만 바꿉니다.

```text
PBL/START.md를 읽고 이 프로젝트에 적용해줘.
만들 것은 라즈베리파이와 ESP32 사이의 UART 센서 데이터 수신 기능이야.
이걸 하면서 인터럽트와 링버퍼를 직접 설명하고 고칠 수 있게 되고 싶어.
기존 코드를 확인하고, 가까운 단계부터 구현하고 검증해줘.
```

- **배우고 싶은 것:** 함께 말하면 AI가 project/project.md의 학습 목표에 적습니다.
  - 어떤 개념을 먼저 짚을지 정하는 기준이 됩니다.
  - 말하지 않아도 진행됩니다.
- **새 프로젝트:** 만들 것을 설명하면 됩니다.
- **기존 프로젝트:** AI가 현재 코드와 기록부터 확인합니다.
- **권한:** 파일 수정과 명령 실행은 사용하는 AI 환경에서 허용해야 합니다.

## 2. 다음 대화에서도 이어 하기

새 대화나 다른 AI로 옮기면 같은 프로젝트 폴더를 제공하고 다음을 붙여넣습니다.

```text
PBL/START.md와 현재 프로젝트 기록을 읽고 이어서 작업해줘.
현재 Step과 마지막 검증 결과를 확인한 뒤 다음 작업을 진행해줘.
```

- **새 대화 권유:** Step 하나가 끝나면 AI가 새 대화로 넘어가기를 권합니다.
  - 대화가 길수록 매 요청의 토큰 비용이 커지기 때문입니다.
  - 위 문장으로 이어 가면 됩니다.
- **AI가 읽어야 할 것:** START.md 텍스트만 전달하면 지침만 넘어갑니다.
  - 이전 진행을 이어 가려면 project/, concepts.html, 필요한 practice/와 코드도 AI가 읽을 수 있어야 합니다.
- **같은 대화 안에서는** 매번 START.md를 붙일 필요가 없습니다.

## 3. 평소에는 이렇게 말합니다

구현 계속:
```text
계속 구현해줘. 기능 단위로 검증하고 관련 기록도 갱신해줘.
```

구현은 됐는데 이해가 안 될 때:
```text
수신 데이터가 버퍼에서 처리 함수까지 가는 흐름이 이해 안 돼.
현재 코드를 기준으로 실제 데이터 하나가 이동하는 과정을 설명해줘.
```

직접 해 보고 싶을 때:
```text
링버퍼를 직접 수정해보고 싶어. practice/에 작은 실습을 만들어줘.
설명부터 길게 하지 말고 간단한 예제에서 시작해줘.
```

실습 확인:
```text
practice/의 내 답과 코드를 확인해줘.
내 답을 고치지 말고 틀린 부분과 필요한 힌트만 알려줘.
```

목표 변경:
```text
UART 직접 연결 대신 RS485 버스로 바꾸자.
기존 결과와 학습 기록을 보존하고, 영향을 받는 단계와 설정을 갱신해줘.
```

결과 정리:
```text
지금까지 기록으로 발표용 한 쪽 요약을 만들어줘.
```

상태 확인:
```text
지금 동작하는 것, 아직 검증하지 못한 것, 내가 이해를 확인하지 않은 부분을 짧게 보여줘.
```

## 4. 직접 볼 파일은 네 종류입니다

| 보고 싶은 것 | 열 파일 |
|---|---|
| 무엇을 했고 왜 통과했는가 | project/Steps/S01.md 등 |
| 값·정책을 왜 골랐고 바꾸면 어떻게 되는가 | project/params.html |
| 내가 무엇을 이해하지 못했거나 아직 확인하지 않았는가 | concepts.html (상태별 보기, 이해 수준, 학습자 메모) |
| 전체가 어떻게 동작하는가 | project/flowchart.html |

HTML 화면 사용법
- 브라우저에서 파일을 직접 엽니다. 서버 실행·JSON 불러오기·로그인이 필요 없습니다.
- 검색과 상태별 보기, 상세 펼치기를 제공합니다.
- 화면은 읽기 전용입니다. 고칠 내용은 AI에게 말하고, 저장 후 브라우저를 새로고침합니다.

화면 예시
- 빈 템플릿에는 실제 결과가 없습니다. 채워진 모습은 examples/demo/에서 볼 수 있습니다.
- 예시 내용은 설명용이며 시험이나 학습 통과 증거가 아닙니다.

## 5. 알아둘 점

AI가 하는 일과 하지 않는 일
- 지침을 읽고 따르는 주체는 AI입니다. 파일 자동 감시·자동 평가·백그라운드 알림은 없습니다.
- 코드 변경을 자동으로 감지하지 않습니다. 변경 영향은 AI가 기록합니다.
- 검사 도구(tools/check.py)는 기록의 형식과 연결 오류만 확인합니다.

학습
- 구현 중 설문·선행 퀴즈·학습 통과 대기는 없습니다. 결과를 바꾸는 요구사항이 불명확할 때만 질문합니다.
- 학습은 요청할 때 진행합니다. 계속 미루면 미확인 항목이 남습니다.
- Step을 마칠 때 AI가 미확인 개념 1~2개와 짧은 실습을 한 줄로 제안합니다. 응하지 않아도 다시 묻지 않습니다.
- 이해 수준은 설명 → 수정 → 직접 수행 3단계로 기록합니다.
  - 직접 해 본 것만 올라갑니다.
  - 설명을 들은 것만으로는 바뀌지 않습니다.

기록과 토큰
- 기록 안에는 현재 상태만 둡니다. 이전 값과 이전 평가는 git 기록으로 봅니다.
- git이 없으면 AI가 처음에 한 번 제안합니다. 원하지 않으면 project/evidence/history.md에 한 줄씩 남깁니다.
- 읽기 범위·명령 출력·대화 길이·갱신량을 줄이도록 설계했습니다. 실제 토큰 절감률은 측정하지 않았습니다.

내부 기록 형식은 guide/records.md에 있습니다. 사용자가 읽거나 명령을 외울 필요는 없습니다.
