# 실습 01 — FastAPI 기초 (약 15분)

연결: 개념 C19(FastAPI 기초), C01(멱등성) · 실제 코드 project/src/kitbot/api.py, schemas.py · Step S01

## 목표
- 요청 → 검사 → 응답 흐름을 직접 보고 응답 코드를 예측할 수 있다.
- 요청이 코드 어디에서 걸러지는지 찾을 수 있다.
- 간단한 조회 주소 하나를 직접 추가할 수 있다.

## 준비 (VS Code 터미널, 저장소 맨 위 폴더 SO_ARM101에서)
```
.venv\Scripts\python practice\01-fastapi\my_api.py
```
- 브라우저에서 http://127.0.0.1:8000/docs 를 연다.
- 가짜 로봇(Mock)으로 동작하므로 장비는 필요 없다. 끝낼 때는 터미널에서 Ctrl+C.
- 실습용 DB는 practice/01-fastapi/var/에 생긴다(git에 올라가지 않음). 처음부터 다시 하려면 var 폴더를 지운다.

## 과제 1 — 예측 후 실행
1. **먼저** answers.md의 표에 요청마다 예상 응답 코드와 이유를 적는다. 서버를 보내 보기 전에 적는다.
2. /docs → `POST /orders` → **Try it out** → 요청 본문을 붙여 넣고 **Execute**.
3. 실제 응답 코드(Responses 아래 Code)를 표에 적는다. 예측과 다르면 왜 다른지 한 줄 적는다.

## 과제 2 — 따라가기
answers.md의 질문에 답한다. project/src/kitbot/schemas.py와 api.py를 열어 찾아본다.

## 과제 3 — 수정: `GET /colors` 추가
- my_api.py의 TODO 부분을 채워, 주문에 쓸 수 있는 색 목록을 `{"colors": ["red", "green", "blue"]}` 형태로 돌려준다.
- 조건: 색 이름을 코드에 직접 쓰지 않는다. 설정값이 바뀌면 응답도 따라 바뀌어야 한다.
- 확인 방법 1: 서버를 켜고 /docs에서 `GET /colors` 실행.
- 확인 방법 2 (자동 시험):
  ```
  .venv\Scripts\python -m pytest practice\01-fastapi -q
  ```
  처음에는 실패하는 것이 정상이다. 3개 모두 통과하면 완료.

## 막히면
- AI에게 "practice 01 과제 N 힌트 하나만"이라고 요청한다. 힌트는 한 단계씩 준다.
- 완성 답을 요청하면 받을 수 있지만, 그 부분은 이해 확인 근거로 쓰지 않는다.
- 끝나면 "practice 01 점검해줘"라고 요청한다. 답 원문은 고치지 않고 평가만 한다.
