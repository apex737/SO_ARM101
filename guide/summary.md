# 결과 정리 — 사용자가 요청할 때만 읽기

발표·제출·회고용 요약을 기록에서 만든다.

- 새로 조사하지 않는다.
- 코드를 통째로 다시 읽지 않는다.

## 1. 읽을 것
- project/project.md
- 각 Step의 판정·검증 이력·결정
- flowchart·params·concepts의 pbl-data (필요한 항목만 추출)

## 2. 쓸 곳
- project/summary.md에 쓴다.
- 이미 있으면 바뀐 부분만 고친다.

## 3. 구성
| 항목 | 내용 |
|---|---|
| 만든 것과 목표 달성 여부 | 목표 ID별로 관련 Step의 현재 판정을 그대로 옮긴다 |
| 동작 구조 | flow의 블록·연결을 짧게, 대표 trace 하나 |
| 주요 결정 | 결정 ID · 선택 · 버린 대안 · 근거 종류 |
| 중요한 값 | params의 값 · source · 바꾸면 생기는 영향 |
| 배운 것 | 학습 목표별로 확인됨 개념, 이해 수준(설명/수정/직접 수행), 확인 조건. 미확인·이해 공백은 따로 적는다 |
| 남은 일과 한계 | 미검증·실패·재검증 필요 Step, 측정하지 않은 것 |

## 4. 지킬 것
- 판정을 올려 쓰지 않는다. 미검증은 미검증, 추정은 추정으로 쓴다.
- 학습 확인은 사용자의 실제 수행 근거가 있는 것만 쓴다.

## 5. 형식과 분량
- 사용자가 형식(발표 슬라이드 개요, 보고서, 한 쪽 요약)이나 분량을 말하면 그에 맞춘다.
- 말하지 않으면 한 쪽 분량으로 쓴다.
