# 프로젝트

- 이름: KitBot — 주문에 맞춰 부품을 담는 작업 키트 구성 로봇 (SO-ARM101)
- 코드 위치: project/src/kitbot/ (게이트웨이 패키지), project/src/tests/ (시험), project/src/requirements*.txt (실행/개발/비전). 원 요구: project/src/pjt.md. 비전 예제: project/src/01~03-*.py
- 현재 작업: S01 통과(Mock 기준). 다음 S02 운영 모니터링 화면 — 사용자 확인 대기: Pi 모델·OS, 암·카메라 연결 위치, 부분 키트 허용 여부
- 환경·제약: 확인된 정보만 기록
  - 구성(사용자 답변 2026-11-09): Pi = 게이트웨이(API·대기열·DB·로봇 통신), 정책 추론 = GPU PC. 카메라 = RealSense + USB 웹캠. 리더암 있음, 정책은 데이터 수집부터.
  - 개발 PC(실측): Windows 11, Python 3.11.9, NVIDIA RTX 4050 Laptop 6GB, 개발용 가상환경 .venv/
  - 미확인: Pi 모델·OS, 이 개발 PC가 추론용 GPU PC인지, 카메라 모델·설치 위치, 암·카메라가 Pi와 GPU PC 중 어디에 USB로 연결될지, 네트워크(유선/무선)

## 우선순위·불변 조건·비목표
- 우선순위: 객체 인식 + 그리퍼 학습 전략(사용자: "결국 핵심") · 추론 속도 · 실패 인식과 재시도.
  - 신뢰성 기능(pjt.md 7번)은 6번까지 진행하며 필요할 때 옵션으로 붙인다. S01에서 이미 만든 부분은 유지한다.
  - 최종 구현 형태는 설계 토론으로 정해 간다(2026-11-09 시작).
- 불변 조건
  - 로봇은 한 번에 작업 하나만 수행한다.
  - DB가 주문·작업 상태의 원본이다. 재시작해도 접수한 주문을 잃지 않는다.
  - 물리 상태를 알 수 없으면(복구 실패·드라이버 무응답) 자동 진행을 멈추고 운영자 리셋을 기다린다.
  - 수행하지 않았거나 확인하지 않은 동작을 성공으로 기록하지 않는다.
- 비목표(현재): 다중 로봇, 인증·암호화(LAN 내부 가정), 클라우드 배포.
