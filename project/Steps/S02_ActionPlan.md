# S02 실행 순서: 학습 없이 블록을 집어 바구니에 넣기

S02.md가 "무엇을 왜, 결과가 어땠나"라면, 이 문서는 "실제로 무엇을 어떤 순서로 하나"다.
모든 명령은 conda lerobot 환경에서 `project/src` 폴더에서 실행한다.

```bash
source ~/miniforge3/bin/activate lerobot
cd ~/Desktop/SO_ARM101/project/src
```

## 진행 상황 (2026-11-10)

| 단계 | 상태 | 결과 |
|---|---|---|
| 0. 시작 전 준비 | 완료 | 카메라 설정 고정, 장대 고정 |
| 1. 자세 저장 (teach) | 완료 | HOME, 그리퍼 벌림 33.8 / 닫힘 1.3, BASKET(그리퍼 끝 높이 약 160mm) |
| 2. 화면 → 로봇 보정 (collect_calib) | 완료 | 보라 블록 14곳, 한 점 빼고 오차 평균 6.0 / 최대 11.1mm |
| 3. 계산만 (pick --dry) | 완료 | 계획 성공 (들어 올림 60 → 40mm로 바꾼 뒤) |
| 4. 접근 오차 재고 보정 (--no-place) | **진행 중** | 두 부리 가운데 기준으로 바꾸고 기존 5건 변환, 스냅샷 `jawcenter5`. 실물로 다시 확인할 차례 |
| 5. 끝까지 (집기 → 바구니 → HOME) | 대기 | |

## 팔이 굳어 있을 때

teach·collect_calib·pick은 끝나도 **팔로워암의 힘을 유지**한다. 프로그램이 끝나는 순간 힘이 풀리면 팔이 테이블로 떨어지기 때문이다. 그래서 끝난 뒤에는 팔이 굳은 채로 있고 손으로 움직일 수 없다.

| 상황 | 원인 | 할 일 |
|---|---|---|
| 프로그램이 끝났는데 팔이 안 움직임 | 힘 유지 (정상) | 팔을 손으로 받치고 `python -m kitbot_exec.release` |
| `--step` 실행 중 팔이 멈춰 있음 | 터미널에서 Enter를 기다리는 중 | 터미널을 클릭하고 Enter |
| 다음 프로그램을 실행하면 다시 움직임 | 새 프로그램이 팔을 다시 잡음 | 그대로 진행 |

## 0. 시작 전에

1. 다른 프로그램을 끈다. 같은 카메라나 같은 팔 포트를 두 프로그램이 동시에 열 수 없다.
   - 위 카메라 라이브 창(view_blocks)은 q로 닫는다.
   - 원격 조종(lerobot-teleoperate)도 끈다.
2. 카메라 장대가 고정되어 있는지 본다. 보정한 뒤 카메라가 움직이면 2단계를 다시 해야 한다.
3. 카메라 설정을 적용한다: `python -m kitbot_exec.camera_lock apply`
4. 블록 색은 **보라(purple)**를 쓴다. 빨강은 팔로워 그리퍼 부리(빨강)와 섞여 검출된다.
5. 화면 안에 보라 블록은 **하나만** 둔다. 바구니 안에 있는 것도 화면에 보이면 센다.

## 1. 자세 저장 (`python -m kitbot_exec.teach`)

로봇은 스스로 움직이지 않는다. 리더암을 손으로 움직이면 팔로워암이 따라오고, 원하는 자세에서 터미널에 글자를 치고 Enter를 누르면 `kitbot_exec/poses.json`에 저장된다.
실행 전에 리더암을 팔로워암과 비슷한 자세로 맞춰 둔다. 두 자세가 많이 다르면 실행하는 순간 팔로워가 휙 움직인다.

| 키 | 리더암으로 맞출 것 | 저장되는 것 | pick에서 쓰는 곳 |
|---|---|---|---|
| `h` | 카메라가 블록 작업 영역을 볼 수 있게 팔을 비킨 자세 | 관절 자세 HOME | 시작·끝 자세, 이 자세에서 카메라로 블록을 찾음 |
| `g` | 팔로워 부리 안쪽 간격이 약 45mm | 그리퍼 값만 | 블록 위로 내려가기 전에 이만큼 벌림 |
| `c` | 그리퍼를 빈 채로 끝까지 닫음 | 그리퍼 값만 | 집을 때 닫는 값, 들어 올린 뒤 이 값까지 닫혀 있으면 "빈손" |
| `b` | 그리퍼 끝이 바구니 안쪽 위, `p`로 보면서 높이 z 120mm 이상(벽 80mm + 블록이 매달리는 길이 + 여유). 비스듬해도 됨 | 관절 자세 BASKET | 블록을 들고 이 자세로 가서 그리퍼를 열어 떨어뜨림 |
| `p` | 아무 자세 | 저장 안 함 | 그리퍼 끝 x(앞), y(왼쪽), z(위) mm와 수직에서 기운 각도 출력 |
| `q` | | | 끝내기. 팔로워는 힘을 유지한 채 멈춰 있음 |

- 순서는 상관없고, 같은 키를 다시 치면 덮어쓴다.
- 블록 위치는 저장하지 않는다. 블록에 접근하고 집는 자세는 매번 카메라와 역기구학으로 자동 계산된다.
- 다시 저장해야 하는 때: 바구니나 로봇 위치를 바꿨을 때.

방향 확인 (`p` 출력):

| 리더암으로 이렇게 하면 | 이 숫자가 커져야 정상 |
|---|---|
| 팔을 앞으로 뻗는다 | x |
| 팔을 왼쪽으로 돌린다 (로봇 뒤에서 앞을 볼 때) | y |
| 팔을 위로 올린다 | z |
| 그리퍼를 수직 아래로 향하게 한다 | "기움"이 0°에 가까워짐 |

## 2. 화면 → 로봇 보정 (`python -m kitbot_exec.collect_calib --color purple`)

같은 지점을 카메라(픽셀)와 로봇(mm)으로 각각 읽어 짝을 짓는다. 로봇이 정확히 아는 위치는 자기 그리퍼 끝뿐이라, **그리퍼 끝을 블록 윗면에 직접 대야** 그 지점의 로봇 좌표를 읽을 수 있다.

한 점마다:

1. 블록을 작업 영역 한 곳에 놓는다. 팔을 비킨 채 **카메라 창을 클릭하고**(영문 입력) `d`를 누른다. 블록 중심 픽셀이 기록된다.
2. 리더암으로 부리를 닫고, 그리퍼를 수직에 가깝게 세운다. 두 부리 끝을 블록 윗면 가운데에 **실제로 닿게** 한다(누르지 말고 닿기만). 그리고 `r`을 누른다.
3. 터미널에 나오는 "높이 z"가 앞 점들과 비슷한지 본다. 8mm 넘게 다르면 경고가 뜬다. 그때는 `u`로 지우고 다시 찍는다.
4. 블록을 옮겨 반복한다. 작업 영역 전체에 고르게 **9곳 이상**, 가장자리도 포함한다.

- 끝내기: `q`, 또는 터미널에서 Ctrl+C. 이번에 점을 추가하거나 지웠다면 **끝낼 때 자동으로 변환을 계산해 `calib_top.json`에 저장**한다(`f`를 눌러도 같음).
- 합격 기준: 터미널의 "한 점 빼고 오차"가 평균 5mm 안팎, 최대 10mm 이하. 가장자리 점은 조금 크게 나오는 게 보통이다.
- `--fresh`: 이전 점을 버리고 새로 시작. 없으면 `var/calib_pairs.json`에 이어서 기록한다.
- `--fit-only`: 팔·카메라 없이 저장된 점으로 계산만 다시 한다.

자주 한 실수:

| 실수 | 결과 |
|---|---|
| 그리퍼를 블록 위 2~5cm에 띄운 채 `r` | 닿은 높이가 20~72mm로 흩어지고 오차 평균 16mm (1차 보정을 버린 이유) |
| 터미널을 보다가 그대로 `f` | 키가 터미널로 들어가 무시됨. 이제는 끝낼 때 자동 계산하므로 상관없음 |
| 빨강 블록 사용 | 그리퍼 부리가 블록으로 잡혀 "블록 2개" 또는 잘못된 위치 기록 |

## 3. 계산만 해 보기 (`python -m kitbot_exec.pick --color purple --dry`)

팔은 움직이지 않는다. 블록 하나를 작업 영역에 두고 실행한다.

출력 읽는 법:

| 줄 | 확인할 것 |
|---|---|
| 검출: 흔들림 최대 …mm | 1~2mm 이하면 좋음 |
| 블록 (로봇 좌표) x, y, z_top, yaw | x, y가 보정 때 찍은 범위 안인가. yaw는 손목을 돌릴 각도 |
| 계획: z_pre, z_grasp, z_lift … | 나오면 성공(`dry_ok`). 높이는 모델 기준이라 z_grasp가 음수여도 정상(모델 0점이 테이블보다 약 2cm 위) |
| 계획 실패 → … | 이유 문장을 그대로 확인. "닿지 않음"이면 블록이 받침대에 너무 가깝거나 멀다 |

## 4. 블록 위 접근 오차 재고 보정하기 (`python -m kitbot_exec.pick --color purple --no-place --step`)

자로 재지 않는다. **리더암으로 팔로워를 정확한 위치에 옮기면, 관절값으로 실제 어긋남(화면 상하좌우 mm + 각도)을 계산해 기록**하고, 다음 실행부터 자동으로 보정한다.
이 모드에서는 리더암도 연결하므로 원격 조종 프로그램이 꺼져 있어야 한다.

1. Enter를 눌러 가며 진행: HOME → 블록 검출 → 블록 위 4cm로 이동 + 손목 회전.
2. **리더암 맞추기:** 터미널에 "관절 차이"가 실시간으로 나온다. 리더암을 지금 팔로워암 자세와 똑같이 맞춘다(손목 회전 포함). 모든 관절이 15° 안이면 Enter.
   - 이 단계가 필요한 이유: 차이가 큰 채로 연결하면 팔로워가 리더 자세로 휙 움직인다.
3. **정확한 위치로:** 팔로워가 리더를 따라 움직인다. 두 부리 가운데를 블록 중심 바로 위(1cm쯤)로, 부리 방향을 블록 면과 나란히 맞춘다. 그리퍼는 수직에 가깝게(기울기 10° 안).
   - 터미널에 "처음 위치 대비: 화면 오른쪽 … 위 … mm | 회전 …° | 높이 … | 기울기 …"가 실시간으로 나온다.
4. 맞췄으면 Enter → 어긋남이 `var/approach_corrections.json`에 한 건 기록되고, 블록 위 접근 높이를 거쳐 HOME으로 돌아간다. 취소는 `x` Enter.
5. 블록 위치와 각도를 바꿔 반복한다. 가까운 곳, 먼 곳, 가장자리를 섞어 **6건 이상**.

출력 읽는 법:

| 줄 | 뜻 |
|---|---|
| 접근 보정 N건, … | 실행 시작 때 지금 적용 중인 보정 |
| 보정 적용: 카메라 (…) → (…) | 카메라 계산값에 보정을 더한 목표 |
| 이번 어긋남 (보정 적용 후) | **이번 시도가 얼마나 틀렸나** (S02 판정 값) |
| 카메라 계산 대비 전체 차이 | 보정을 계산하는 데 쓰는 값 (보정 전 기준) |

보정 방식:

| 기록 수 | 적용 방법 |
|---|---|
| 0건 | 보정 없음 |
| 1~5건 | 평균 어긋남을 모든 위치에 똑같이 더함 (일정한 밀림) |
| 6건 이상 | 위치마다 다른 밀림을 x, y의 1차식으로 맞춤 |
| 각도 | 평균 차이를 더함 |

- 합격 기준: "이번 어긋남"이 화면 상하좌우 모두 10mm 이내(그리퍼 벌림 45mm − 블록 25mm의 절반), 각도는 부리가 블록 면과 나란히 들어갈 정도.
- 보정 없이 비교하려면 `--no-correction`. 보정을 처음부터 다시 하려면 `var/approach_corrections.json`을 지운다.
- 카메라나 보정(2단계)을 다시 했으면 이 기록도 지우고 다시 모은다.
- 잘 맞는 상태는 `python -m kitbot_exec.snapshot save 이름`으로 저장해 두고, 틀어지면 `restore`로 되돌린다.

## 5. 끝까지 (`python -m kitbot_exec.pick --color purple --step`)

HOME → 블록 위 → 내려가기 → 집기 → 들어 올리기(블록 윗면 위 40mm) → 잡았는지 판정 → 작업 영역 위에서 BASKET 높이로 → 어깨만 돌려 바구니 위로 → 놓기 → 어깨 먼저 돌리고 HOME.

- 들어 올린 뒤 그리퍼가 빈손 닫힘 값까지 닫혀 있으면 "빈손"으로 판정하고, 그리퍼를 연 뒤 HOME으로 돌아온다.
- 떨어뜨린 블록이 바구니 밖으로 튀어 나가는지 본다(BASKET이 높고 기울어 있음).
- 단계마다 문제없으면 `--step` 없이 한 번에 돌린다.
- 매번 결과가 `var/pick_log.jsonl`에 한 줄씩 남는다.
