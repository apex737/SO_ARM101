# S05 — ACT 학습: 접근 이후 보정 → 집기 → 바구니 → HOME

- ID: S05
- 목표 연결: G3 (학습에 쓰지 않은 위치에서 바구니 넣기 80%), G4 (추론 지연 측정)
- 선행 단계: S02 (통과 2026-11-11, 인계 조건 D11). S03·S04보다 먼저 시작한다(2026-11-11 사용자 결정).
- 현재 판정: 미검증
- 관련 코드: project/src/kitbot_exec/ (접근: pick.py·exp_s02.py, 팔: arm.py), LeRobot 0.6.0 (conda lerobot). 시작 자세 approach.py, 시연 녹화 record_act.py(S05-1), 정책 실행 run_act.py(S05-4)
- 관련 흐름/설정/개념 ID: S02 D09(역할 분담)·D11(인계 조건), 설정 P16(집기 직전 벌림)·P17(접근 높이)·P18(두 부리 가운데)

## 무엇을 왜 하는가
CV+IK가 블록 위 약 40mm까지 데려다 놓은 상태에서, ACT가 남은 어긋남을 손목 카메라로 보정하고 → 내려가 집고 → 바구니에 넣고 → HOME으로 돌아온다(S02 D09).
접근을 계산이 맡으므로 ACT가 보는 시작 상태가 좁다. 그만큼 시연 수를 줄이고, 처음 보는 위치에서도 같은 일을 하게 만드는 것이 목적이다.

## 넘어가는 조건 (S02 → S05 인계, S02 D11에서 확정)
**시연을 녹화하는 날과 실행하는 날 모두** 아래가 맞아야 한다. 하나라도 바뀌면 그 전 시연과 새 시연은 서로 다른 조건이다.

| 항목 | 값 | 확인 방법 |
|---|---|---|
| 시작 자세 | 보정 없는 CV+IK 접근(`--corr none`): 두 부리 가운데가 블록 위 40mm(명령, 실제 약 33~35mm), 손목 회전 = 블록 각도, 그리퍼 열림(33.8) | 접근 직후 출력 |
| 작업 영역 | 로봇 좌표 x 95~145, y 100~220mm (위 카메라 `view_blocks --grid`의 초록 원 9개가 덮는 영역) | `view_blocks --grid` |
| 블록 | 보라 1개, 다른 블록과 떨어져 있음 | 위 카메라 검출 1개 |
| 남은 오차(ACT가 보정할 범위) | 위치 최대 10mm(평균 6), 각도 최대 9.8°(평균 −4°). 받침대 가까운 줄은 움직이는(검정) 손가락 쪽으로 7~10mm | S02 report_grid.json |
| 고정 파일 | 스냅샷 `src/calibration/snapshots/2026-11-11_1225_s02_eval_pass` (화면→로봇 보정, 자세, 카메라 설정, 팔 캘리브레이션) | `snapshot list`, 파일 비교 |
| 장비 배치 | 위 카메라 장대, 바구니, 로봇 받침대 위치 그대로 | 아래 "세션 시작 점검" |

**실행 중 인계 판단** (매 시행, 별도 로직이 판단. ACT에 넘기기 전에):
1. 계획 성공(역기구학·안전 검사 통과)
2. 접근 직후 관절 (목표 − 실제) 최대 4° 이하. 평소 2.2~2.6°(팔꿈치)이며, 4°는 추정 기준이다.
3. 손목 카메라에 블록 검출

하나라도 아니면 ACT를 시작하지 않고 HOME으로 돌아가 다시 접근한다. 두 번 연속 실패하면 실패로 기록한다.

**세션 시작 점검** (녹화·평가 날마다 10분):
```bash
source ~/miniforge3/bin/activate lerobot && cd ~/Desktop/SO_ARM101/project/src
python -m kitbot_exec.camera_lock apply
python -m kitbot_exec.exp_s02 --color purple check
python -m kitbot_exec.exp_s02 --color purple straddle --name session_chk --step   # 블록을 g05에, 사람 판정이 c(가운데)여야 함
```
`c`가 아니면 장비가 움직였다는 뜻이다. 그날 녹화를 멈추고 S02 5단계 평가를 다시 한다.

## 학습 유의사항
### 시연 녹화
| # | 유의사항 | 이유 |
|---|---|---|
| 1 | **모든 시연은 실제 CV+IK 접근이 끝난 자세에서 시작한다.** 손으로 옮겨 놓은 자세에서 시작하지 않는다 | 실행 때 ACT가 받는 시작 상태(서보 처짐 포함)와 같아야 한다 |
| 2 | **접근 목표를 일부러 흔든다**: 위치 ±15mm, 각도 ±15° 안에서 고르게 | S02 남은 오차(10mm, 10°)보다 넓게 담아야 처음 보는 어긋남도 보정한다. 흔들지 않으면 ACT는 "이미 맞은 상태"만 배운다 |
| 3 | 흔든 값(dx, dy, dyaw)과 접근 진단(관절 차이, 손목 사진 오차)을 에피소드마다 함께 기록한다 | 실패가 어느 시작 조건에서 몰리는지 나중에 나눌 수 있다 |
| 4 | 리더암을 팔로워 자세에 **관절 차이 15° 안으로 맞춘 뒤에** 녹화를 시작한다 (화면에 차이 표시) | 차이가 크면 녹화 시작 순간 팔로워가 튄다(2026-11-10 토론에서 가장 막힐 지점으로 꼽음) |
| 5 | 한 에피소드 = 접근 완료 → 보정·내려가기 → 집기 → 들어 올리기 → 바구니 위에서 놓기 → **HOME 자세로 끝** | 시작과 끝이 매번 같아야 학습이 쉽다. HOME은 poses.json의 home에 가깝게 |
| 6 | 동작은 천천히, 매번 비슷한 순서와 속도로. 집기 전에 손목 사진에서 블록이 두 손가락 가운데 오도록 먼저 맞추고 내려간다 | ACT는 시연의 습관을 그대로 배운다. 머뭇거림·되돌아감도 배운다 |
| 7 | 실패한 시연(놓침, 바구니 밖)은 그 자리에서 버린다(`←`/`r`) | 실패 감지·복구는 별도 로직 담당(D09). ACT에는 성공 동작만 |
| 8 | 블록 위치는 작업 영역 전체에 고르게, 블록 각도는 −45~45°에 고르게 | 한쪽에 몰리면 다른 쪽에서 무너진다 |
| 9 | **평가용 위치는 시연에 쓰지 않는다**: g01~g09 원 중심에서 2cm 안에는 블록을 놓지 않는다 | G3 "학습에 쓰지 않은 위치" 조건. S02 평가 위치를 그대로 시험 위치로 쓴다 |
| 10 | 첫 묶음은 50개(추정)로 학습·평가한 뒤 늘린다 | 6GB GPU에서 학습 시간을 보고 정한다 |

### 관찰·동작 데이터
| # | 유의사항 | 이유 |
|---|---|---|

## 사전 통과 기준 (제안, 사용자 확인 전, 수치는 추정)
- 학습에 쓰지 않은 위치(g01~g09 × 0°·30°, 18회)에서 바구니 넣기 + HOME 성공 80% 이상(G3와 같은 기준).

- 못 넘으면: 실패 구간(집기/바구니/HOME)과 시작 조건별로 나눠 기록하고 시연 추가·범위 조정을 정한다.

## 구현과 주요 결정
- D01 넘기는 높이 후보: 40mm 접근 뒤 블록 윗면 위 약 15mm(명령)까지 수직 하강해서 넘기기 (2026-11-11, 사용자 경험 + S02 데이터, 제안)
  - 근거: S02 straddle·chk 6회에서 하강한 자리의 관절 (목표 − 실제)가 0.2~0.8°로, 40mm 접근 직후(2.2~2.6°)보다 작았다(천천히 내려간 효과일 수도 있음). 손목 사진에 손가락 끝과 블록이 같은 높이로 함께 보여 어긋남이 그대로 보인다.
  - 대가: 흔들기(±15mm)와 겹치면 손가락 끝이 블록 윗면 바로 위를 지난다 → 블록 윗면 아래로는 내리지 않는다(5mm 미만 거부). 옆 블록 간격이 흔드는 폭보다 넓어야 한다.
  - 다시 판단할 조건: 리더암 자동 맞춤 실험 결과, 첫 시연 10개의 집기 성공 여부.
- D02 리더암 맞춤: 자동 맞춤(리더암 서보 힘 40%로 팔로워 자세까지 이동 → 사람이 잡으면 힘 풀기)을 실물로 먼저 시험한다(2026-11-11 사용자 결정). 안 되면 사람이 관절 차이를 보며 맞춘다. 명령: commands.md 2-4.
  - 원칙: 팔로워와 블록 사이 어긋남은 넓게(흔들기), 리더암과 팔로워 사이 차이는 0에 가깝게. 둘은 다른 양이다.
  - 손 맞춤 추가(2026-11-11 사용자 결정): 자동 맞춤 뒤 힘을 풀면 차이가 5°를 넘는 일이 잦았다(시험 ep1 4.84°, 사용자 관찰 "자주 이탈"). → 자동 맞춤은 유지하고, 그 뒤 팔로워를 멈춘 채 관절별 차이를 실시간으로 보여 주며 사람이 리더암을 맞춘다. 모든 팔 관절 3° 이하(그리퍼 3 이하)일 때 Enter로 녹화 시작(`f` = 그래도 시작, `a` = 자동 맞춤 다시, `s` = 건너뛰기, 선택 `--auto-start-s`). 녹화 시작 때 차이·손 맞춤 시간을 에피소드 기록에 남긴다(`leader.max_gap_at_start_deg`, `fine_tune_s`).
- D03 흔들기 범위 (2026-11-11, 제안, 사용자 질문 "CV가 잘 맞으면 굳이 흔들어야 하나")
  - 흔드는 이유: CV 접근 오차가 평균 6mm·최대 10mm이고 위치에 따라 치우침(g01 7~10mm), 장비가 조금 움직인 날·보정 범위 가장자리에서는 더 커진다. 흔들지 않은 시연만 있으면 ACT는 "이미 가운데"인 장면만 보고 배워, 실행 중 어긋난 장면에서 고치는 동작을 모른다(모방학습의 시작 상태 차이 문제).
  - 범위 제안: 절반은 흔들지 않음(CV 그대로), 절반은 반지름 10mm·±10° → `--jitter-prob 0.5 --jitter-mm 10 --jitter-deg 10`. CV 자체 오차가 더해져 실제 어긋남은 최대 약 20mm. S05 유의사항 2번(±15mm·±15°)은 상한으로 둔다.
  - 다시 판단할 조건: 첫 학습 평가에서 실패가 큰 어긋남에서 몰리면 범위를 넓히고, 흔든 시연에서 사람이 고치는 동작이 들쭉날쭉하면 좁힌다.
- D04 실행 도구를 직접 만듦: `lerobot-rollout` 대신 `run_act.py` (2026-11-11, 문제 제안 검토 3·4번)
  - 이유: rollout에는 CV 접근 단계가 없고, 카메라 영상에 색 보정(correct_wb)을 하지 않아 녹화 때 영상과 달라진다. 정책은 녹화 때와 같은 입력을 받아야 한다.
  - 정책 불러오기·전처리·후처리는 LeRobot 0.6.0 rollout과 같은 함수를 쓴다(`get_policy_class().from_pretrained`, `make_pre_post_processors`, `select_action`).
  - 멈춤 판정(ACT는 스스로 멈추지 않음): HOME 8° 안 1초 = 끝, 닫으라는 명령인데 명령값(또는 빈손 닫힘값) + 3까지 다 닫힘 0.5초 = 빈손(잡은 뒤면 떨어뜨림), 놓은 뒤 다시 닫는 것은 빈손으로 보지 않음, 명령 그리퍼 끝이 테이블 −10mm 아래면 보내지 않고 멈춤, 30초 시간 초과. 수치는 추정이며 첫 실행 기록(`min_cmd_clear_mm`, 잡은·놓은 시각)으로 다시 정한다.
  - 한 프레임 관절 이동 한도: 처음 5°로 했다가 8°(녹화와 같게)로 바꿈(2026-11-11 시험 녹화 분석). 시연에서 팔 관절 (명령 − 실제)가 5° 넘는 프레임이 에피소드마다 약 140개(돌아가는 구간)였고, 쥐는 동안 그리퍼 명령은 늘 '블록 폭 − 8'이었다. 5°로 줄이면 쥐는 힘과 속도가 시연과 달라진다.
- 시연 일관성 (ACT 평균 문제 대비): 같은 장면에서 다른 전략(어떤 때는 옆에서, 어떤 때는 위에서)을 섞지 않는다. 순서 고정: 손목 화면에서 가운데 맞추기 → 수직으로 내려가기 → 닫기 → 수직으로 올리기 → 비슷한 길로 바구니 → 열기 → HOME.
