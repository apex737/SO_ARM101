# 실험 계획: 보정 범위 안팎에서 순수 IK와 ACT·디퓨전 비교

- 작성일: 2026-11-13
- 관련 기록: [S05.md](S05.md) D06(비교 실험 방법), [S02.md](S02.md) D11(인계 조건)
- 상태: 계획. 아직 시작 전이고, 아래 "만들어야 할 기능"이 먼저 필요하다.

## 한 줄 요약
위 카메라 좌표만 믿고 집는 방식(순수 IK)은 **보정한 범위를 벗어나면 빗나간다.** 손목 카메라로 마지막에 고쳐 잡는 방식(IK+ACT, IK+디퓨전)은 **같은 자리에서도 성공률이 덜 떨어진다.** 이 두 가지를 실제로 재서 보이는 것이 목표다.

## 먼저 알아 둘 말
| 말 | 뜻 |
|---|---|
| 보정점 | 위 카메라 화면의 한 점과 로봇 좌표(mm)의 실제 위치를 짝지어 잰 점. 이 짝들로 "화면 픽셀 → 로봇 mm" 변환식을 만든다. 학습이 아니라 자를 대고 눈금을 맞추는 일이다 |
| 보정 범위 | 보정점들을 이은 볼록한 영역. 지금은 로봇 좌표 x 87~150mm, y 38~239mm |
| 범위 밖 거리 | 블록이 보정 범위에서 몇 mm 떨어져 있는지. 범위 안이면 0 |
| 순수 IK | 위 카메라로 블록 위치를 구하고, 계산(역기구학)만으로 내려가 집어서 바구니에 넣는 방식. 학습 없음 |
| IK+ACT, IK+디퓨전 | 블록 위까지는 순수 IK와 똑같이 가고, 거기서부터 학습한 정책이 손목 카메라를 보며 위치를 고쳐 집고 바구니에 넣는 방식 |
| 접근 오차 | 그리퍼가 블록 위에 왔을 때, 두 손가락 가운데가 블록 가운데에서 얼마나 벗어났는지(mm). 손목 카메라 사진으로 잰다 |

## 왜 이 실험을 하나
최근 순수 IK 시험에서 이런 일이 있었다.
- 블록이 보정 범위 밖(예: 범위에서 20~50mm)에 있으면, 그리퍼가 블록 옆을 건드려 블록을 밀어내고 빈손으로 올라오는 일이 잦았다.
- 블록 인식은 정상이었다. 색과 위치는 제대로 찾았는데, 화면 위치를 로봇 좌표로 바꾸는 과정에서 오차가 컸다.

보정 범위 밖에서 오차가 커지는 이유는 두 가지로 본다.
1. 웹캠이 광각이라 화면 가장자리로 갈수록 상이 휜다(렌즈 왜곡). 지금 변환식은 이 휨을 모른다.
2. 보정점을 잴 때 생긴 작은 오차가, 범위 밖으로 늘려 쓸수록 커진다. 짧은 자로 먼 거리를 재면 끝으로 갈수록 오차가 커지는 것과 같다.

그렇다면 순수 IK에는 늘 "보정 범위"라는 한계가 있고, 손목 카메라로 마지막에 고치는 방식은 그 한계를 덜 탄다는 것이 우리 생각이다. 이걸 말이 아니라 숫자로 보이려는 것이 이 실험이다.

## 무엇을 보이려 하나
| # | 보이려는 것 | 무엇으로 보이나 |
|---|---|---|
| A | 순수 IK는 보정 범위 안에서는 잘 집는다 | 범위 안 성공률, 접근 오차 |
| B | 순수 IK가 범위 밖에서 실패하는 건 보정 범위 때문이다 | 범위 밖 거리가 늘수록 접근 오차가 커지고, 약 10mm(그리퍼를 벌렸을 때의 여유)를 넘는 곳부터 실패가 시작되는 그래프 |
| C | 보정점을 늘리면 그 자리에서 순수 IK도 다시 된다 | B와 **같은 자리**에서 보정만 넓혀 다시 시험 → 성공률 회복 |
| D | ACT·디퓨전은 원래 보정 그대로도 범위 밖 성공률이 덜 떨어진다 | B와 같은 자리, 원래 보정으로 시험 |

D는 "보정점이 필요 없다"는 뜻이 **아니다.** ACT·디퓨전도 블록 위까지는 같은 위 카메라 보정으로 간다. 정확히는 "범위 밖에서 생긴 접근 오차를 손목 카메라로 고쳐서 성공률을 지킨다"는 주장이다. 발표나 보고서에서도 이 표현을 지켜 주세요.

## 시험 자리
- 블록을 놓을 자리를 **미리 12곳 정하고 테이블에 테이프로 표시**한다.
  - 보정 범위 안 6곳: 범위 안에 고르게.
  - 보정 범위 밖 6곳: 범위 밖 거리 10mm, 20mm, 30mm 근처 각 2곳 정도. 바구니 앞, 받침대 오른쪽 옆처럼 지금 자주 실패한 구역을 포함한다.
- 모든 방식이 **같은 자리, 같은 순서, 같은 색**으로 시험한다. 블록 각도도 자리마다 정해 둔다(예: 0°, 30°를 번갈아).
- 한 자리에서 방식마다 2~3회. 칸(방식 × 범위 안/밖)마다 10회 이상이 되게 한다.
  - 10회면 성공률이 ±30%p 정도 흔들린다. 차이가 크게 날 때만 결론을 낸다.

## 실험 순서
| 순서 | 할 일 | 쓰는 보정 | 보이는 것 |
|---|---|---|---|
| 0 | 위 카메라 장대 고정 → 원래 범위 안에서 보정 다시 → 스냅샷 저장 | 원래 범위 (새로 잰 것) | 준비 |
| 1 | 순수 IK, 범위 안 6곳 | 원래 | A |
| 2 | 순수 IK, 범위 밖 6곳 | 원래 | B |
| 3 | IK+ACT, IK+디퓨전, 12곳 모두 | 원래 | D |
| 4 | 보정점을 범위 밖 6곳까지 늘려 **다른 파일로** 저장 → 순수 IK, 범위 밖 6곳 다시 | 넓힌 것 | C |

순서를 이렇게 잡은 이유:
- **0번을 꼭 먼저 한다.** 11-12 오후부터 위 카메라가 4~8mm 밀려 있다. 이 상태로 시작하면 보정 범위 안에서도 빗나가서 A부터 틀어진다.
- **넓힌 보정(4번)은 맨 마지막에 한다.** 같은 보정 파일을 덮어쓰면 ACT·디퓨전의 접근까지 바뀌어 3번 결과가 섞인다. 넓힌 보정은 반드시 다른 파일로 두고, 4번에서만 쓴다.
- ACT·디퓨전(3번)은 원래 보정으로 돌려야 순수 IK(1·2번)와 공정하게 비교된다.

## 결과 정리
1. **방식 × 구역 성공률 표**

   | | 범위 안 | 범위 밖 | 범위 밖 (보정 넓힘) |
   |---|---|---|---|
   | 순수 IK | | | |
   | IK+ACT | | | (해당 없음) |
   | IK+디퓨전 | | | (해당 없음) |

2. **범위 밖 거리 vs 접근 오차 그래프** (순수 IK, 시행마다 점 하나). 10mm 선을 함께 그려, 이 선을 넘는 곳부터 실패가 늘어나는지 본다.
3. **실패 종류별 개수** (g, d, b, x). 순수 IK는 범위 밖에서 g(못 잡음)가 늘 것으로 예상하고, ACT·디퓨전은 어느 구역에서 무엇으로 실패하는지 본다.
4. 대표 영상 몇 개: 범위 안 성공, 범위 밖 순수 IK 실패, 같은 자리 ACT 성공.

## 해석할 때 조심할 점
- **ACT·디퓨전의 시연 범위.** 시연 50개는 블록 x 74~166mm 안에서만 녹화했다. 이보다 훨씬 바깥에서 ACT가 실패하면, 보정 때문이 아니라 정책이 처음 보는 장면이라서일 수 있다. 시험 자리마다 "가장 가까운 시연 자리까지 거리"가 기록되므로, 이것과 나눠서 본다.
- **디퓨전 모델은 데이터가 조금 다르다.** Kaggle에서 학습한 디퓨전은 시연 50개를 모두 썼고(ACT는 불량 4개를 뺀 46개), 이 PC에서는 동작이 끊기며 약 17Hz로 움직인다. ACT와 성공률을 바로 비교할 때 이 차이를 함께 적는다.
- **장비가 움직이면 결과를 버린다.** 실험 날마다 시작 전에 위 카메라 위치(테이프 표시)와 바구니 위치를 확인한다. 중간에 장대를 건드렸다면 그 뒤 결과는 따로 표시한다.
- **바구니는 고정한다.** 바구니 앞 테두리 선을 기준으로 바구니 안 블록을 거르는데, 바구니를 옮기면 이 선도 다시 재야 한다.
- 노트북은 **충전기를 꽂고** 한다. 배터리가 떨어지면 계산이 느려지고 결국 꺼진다(11-12에 학습이 끊긴 원인).

## 지금 상태 (2026-11-13)
- 위 카메라: 11-12 오후부터 밀려 있음(4~8mm). 0번 전에는 실험하지 않는다.
- 순수 IK: 보정 범위 + 25mm 안 블록만 집도록 정해 둠(`--max-outside-mm`로 바꿀 수 있음). 이 실험의 2번에서는 범위 밖 자리를 시험해야 하므로 `--any-place`로 제한을 끄고 돌린다.
- IK+ACT: 20,000단계 모델 있음. 학습에 안 쓴 시연 5개에서 잰 동작 오차는 거의 그대로였다(0.22 → 0.21).
- IK+디퓨전: Kaggle 20,000단계 모델 있음, 실행 파일 준비됨. 실물 성공률은 아직 모른다.
- 큐 실행(`--queue`)은 이 실험에 쓰지 않는다. 자리와 순서를 정해 놓고 한 번에 하나씩 놓는다.
