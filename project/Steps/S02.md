# S02 — 비전 + IK로 블록 위 이동, 손목 각도 맞추기

- ID: S02
- 목표 연결: G3 (처음 보는 위치 80%의 바탕), G4 (지연 측정은 S05)
- 선행 단계: 없음 (S01 게이트웨이와 직접 의존 없음. 연결은 S04)
- 현재 판정: 미검증
- 관련 코드: (작성 예정) project/src/kitbot_exec/ — 노트북 쪽 실행 코드 위치 후보
- 관련 흐름/설정/개념 ID: 개념 C08(2단 접근), C09(컬러-깊이 정렬), C11(카메라-로봇 보정), C12(역기구학)

## 무엇을 왜 하는가
사용자 분해안 1번: 색과 무관하게 블록을 찾고, 계산(역기구학)으로 그리퍼를 블록 위 30~50mm로 보내고, 손목 회전을 블록 각도에 맞춘다.
이 Step의 핵심 질문은 "계산으로 보낸 그리퍼가 실제로 몇 mm, 몇 도 어긋나는가"이다. 이 숫자가 그리퍼 허용 오차 안이면 하이브리드(접근은 계산, 집기는 ACT)로 간다. 훨씬 크고 보정으로 줄지 않으면 방향을 다시 정한다.

## 사전 통과 기준
수치 기준은 측정 전에 정한 추정값이다. 결과를 본 뒤 기준을 바꾸면 이유를 남긴다.

**꼭 실물로 확인할 것 (판정 기준)**
1. 접근 정확도: 작업 영역 격자 9곳 × 블록 각도 2종 이상(예: 0°, 30°)에서 그리퍼를 블록 위 30~50mm로 보낸다.
   - 측정: 그리퍼 중심과 블록 중심의 수평 오차(mm), 그리퍼 각도와 블록 각도 차이(°).
   - 허용 오차 = (그리퍼 최대 벌림 폭 − 블록 한 변) ÷ 2. 그리퍼·블록을 잰 뒤 계산해 여기에 적는다.
   - 통과: 시도의 90% 이상이 허용 오차 안, 각도 오차 10° 이하 (추정 기준. 남는 오차는 ACT가 보정한다는 가정).
   - 통과하지 못하면: 원인(깊이 오차 / 보정 오차 / 서보 유격)을 나눠 기록하고 "탐색 완료"로 닫은 뒤 방향을 다시 정한다.
2. 안전: 테이블 높이 아래로 내려가는 명령과 관절 한계를 넘는 명령을 실행 전에 거부한다.

**Step 안의 작은 확인 (기록만, 판정에 바로 쓰지 않음)**
- 장비: 리더암 → 팔로워암 원격 조종이 끊기지 않는가, 카메라 3대가 동시에 몇 fps로 들어오는가, 서보 값을 초당 몇 번 읽는가.
- 카메라: 노출·화이트밸런스 고정 후 같은 장면의 색값 변동, 작업 거리에서 깊이 오차(mm).
- 블록 검출(색 무관, 깊이 사용): 블록 1~4개 검출 누락 여부, 같은 블록 3D 중심의 반복 편차(mm), 각도 추정 오차(°).
- 팔 기구학: 관절값으로 계산한 그리퍼 끝 위치와 자로 잰 위치의 차이(mm), 같은 자세로 반복 이동 시 편차(서보 유격).
- 카메라-로봇 보정: 보정 후 남는 오차(mm).

## 구현과 주요 결정
- 현재 가정: 위에서 보는 카메라 = RealSense, 손목 = 웹캠 1, 전체·키트 = 웹캠 2. RealSense 모델 확인 후 다시 판단한다(D405면 "위 = 웹캠, 손목 = D405"도 후보). 근거: 2026-11-10-discussion.md 카메라 절.
- 접근 높이: 블록 위 30~50mm (사용자 확정 2026-11-10).
- 블록 각도: 위에서 본 블록 윤곽(최소 외접 사각형)을 테이블 평면 좌표로 옮겨 계산, 정육면체라 손목 회전 ±45° 안에서 정한다.
- LeRobot·카메라 라이브러리는 게이트웨이용 .venv와 분리된 별도 가상환경에 설치한다(LeRobot이 torch 등 큰 의존성을 고정하기 때문).
- 미정(구현할 때 결정 ID를 붙여 기록): 역기구학 방식(해석식 직접 계산 vs 라이브러리), 카메라-로봇 보정 방법(그리퍼 끝을 테이블 위 점 여러 개에 대고 카메라 좌표와 짝짓기 vs 마커).
