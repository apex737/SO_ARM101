# 2026-11-11 실행 계획 — CV+IK 접근을 안정화하고 ACT 인계 조건 정하기

기준: [S02_ActionPlan.md](S02_ActionPlan.md), [S02_BiasFixPlan.md](S02_BiasFixPlan.md), 2026-11-10 현재 코드.

목표 흐름은 **CV+IK로 블록 위 접근 → ACT로 미세 보정·집기·바구니 투입·HOME 복귀**다. 내일은 접근 상태를 측정하고, ACT 시연을 시작할 위치·높이·벌림·잔여 오차를 정한다. 접근이 잘된다는 이유로 ACT의 시작점을 HOME으로 바꾸지 않는다.

이 문서는 Ubuntu 로봇 작업 PC의 **Bash + conda `lerobot`** 기준이다. Windows PowerShell에 그대로 붙여 넣지 않는다. Bash·Python 문법과 모의 장치에서의 진단 저장·취소, 실패한 시행의 보정 복원을 확인했다. 아래 실물 결과는 아직 미검증이다. 저장소의 제어 코드는 수정하지 않는다.

## 실행 순서

| 순서 | 할 일 | 예상 시간 | 실행 조건 |
|---|---|---|---|
| 0 | 환경·기존 상태 보존 | 5~10분 | 항상 |
| 1 | 카메라·저장 자세·기하 상태 확인 | 15~25분 | 항상, 재저장은 필요할 때만 |
| 2 | 계산 점검 + 진단 명령 준비 | 10분 | 항상 |
| 3 | 같은 보정으로 가까이·중간·멀리 반복 접근 | 20~30분 | 항상 |
| 4 | 필요한 보정만 다시 수집 | 20~40분 | 3번에서 반복되는 위치 편향이 확인될 때 |
| 5 | 보정을 고정한 별도 위치 평가 | 30~45분 | 접근이 안정적으로 반복될 때 |
| 6 | 결과 보존·ACT 인계 조건 작성 | 10분 | 항상 |

첫 목표는 3번까지다. 팔이 흔들리거나 관절 추종 차이가 크게 변하면 보정점을 계속 추가하지 말고, 그 조건과 로그를 남긴다. 4번을 생략하고 5번으로 갈 수도 있다.

## 1. 카메라와 기하 상태 확인

### 1-1. 검출 확인 — 팔은 움직이지 않음

```bash
python -m kitbot_exec.view_blocks --role top --color purple --calib kitbot_exec/calib_top.json
```

- 작업 영역에는 **보라 블록 하나**만 둔다. 바구니 속 보라 블록도 화면에 보이면 검출 개수에 포함된다.
- 화면에 `1 block(s)`가 안정적으로 표시되는지 본다. 빨강은 그리퍼 부리와 섞이므로 사용하지 않는다.
- 가까이·중간·멀리 옮겨 검출되는지 확인한다. `s`는 사진 저장, `q`는 종료다. 반드시 종료하고 다음 단계로 간다.
- 이 창의 `jitter`는 **픽셀 표준편차**다. 뒤에서 `pick`이 출력하는 mm 흔들림과 같은 지표가 아니다.

### 1-2. 자세와 모델 확인 — 리더암을 움직이면 팔로워가 움직임

카메라·로봇·바구니 배치가 그대로면 저장 자세를 그대로 사용한다. 저장값이 없거나 배치가 바뀐 경우, 또는 기구학을 확인할 때만 실행한다. **실행 전에 두 팔을 비슷한 자세로 맞춘다.**

```bash
python -m kitbot_exec.teach
```

| 키 + Enter | 할 일 |
|---|---|
| `p` | 현재 관절값, 모델의 그리퍼 끝 좌표·기울기 확인. 저장하지 않음 |
| `h` | 작업 영역을 가리지 않는 HOME을 다시 저장할 때만 |
| `g` | 집기 직전 부리 안쪽 벌림 약 45mm를 다시 저장할 때만 |
| `c` | 빈손으로 닫힌 그리퍼 값을 다시 저장할 때만 |
| `b` | 바구니 안쪽 위의 놓기 자세를 다시 저장할 때만 |
| `q` | 종료. 팔로워의 힘은 유지됨 |

가까이·멀리·옆의 3자세에서 `p`를 보고, 실제 이동 방향과 높이 변화를 자로 확인한다. 같은 물리적 끝점을 기준으로 비교한다. **`p`는 모델의 고정 부리 쪽 끝점이며, 벌린 두 부리 가운데 좌표가 아니다.** 끝점 기준을 확인할 때는 부리를 닫아 비교한다.

실제 높이 변화와 모델 높이 변화가 다르면 자세 의존 오차로 기록한다. 일정한 높이 차이만으로 관절 0점 문제라고 단정하지 않는다. 모델 원점과 테이블의 높이 차이도 확인해야 한다. 이 자리에서 임의로 관절 0점을 바꾸지 않는다.

### 1-3. 카메라↔로봇 보정 재수집 — 배치가 바뀌었을 때만

카메라 장대나 로봇 받침대가 움직였거나 기존 보정이 없으면 실행한다. 같은 배치에서 기존 보정이 남아 있으면 생략한다. 리더암과 팔로워암 자세를 먼저 맞춘다.

```bash
python -m kitbot_exec.snapshot save before_recalib_20261111
python -m kitbot_exec.collect_calib --color purple --fresh
```

1. 작업 영역 전체에 고르게 9~14곳을 정한다. 점들을 한 줄에만 놓지 않는다.
2. 팔을 비킨 뒤 **카메라 창을 클릭하고 영문 입력으로** `d`: 블록 중심 픽셀 기록.
3. 부리를 닫고 수직에 가깝게 세운 뒤, 끝을 블록 윗면 가운데에 살짝 댄다. 공중에 띄운 상태로 기록하지 않는다.
4. `r`: 관절값에서 계산한 좌표 기록. 기울기는 가능한 곳에서 3° 안을 목표로 한다. 높이가 다른 점들과 8mm 이상 다르면 접촉 상태를 확인한다.
5. 명백한 접촉·검출 실수가 있을 때만 `u`로 마지막 점을 취소하고 다시 측정한다. 큰 오차라는 이유만으로 점을 삭제하지 않는다.
6. `q`: 종료. 점을 변경했다면 자동 계산·저장된다. Ctrl+C도 변경된 점이 충분하면 저장하므로 “저장 취소” 기능이 아니다.

`한 점 빼고 오차`의 평균·최댓값을 기록한다. 기존 값은 평균 6.0 / 최대 11.1mm였다. 평균 5mm 안팎·최대 10mm 이하는 개선 목표이며, 이 숫자만으로 실제 접근 성공을 판정하지 않는다.

재보정했다면 기존 접근 보정도 새 좌표계에 맞지 않을 수 있으므로 보존 후 비운다. **아래 명령은 1-3을 수행한 경우에만 실행한다.**

```bash
if [ -f var/approach_corrections.json ]; then
    cp var/approach_corrections.json "$S02_RUN/corrections_before_recalib.json"
fi
printf '[]\n' > var/approach_corrections.json
```

## 2. 계산 점검과 접근 진단 명령 준비

### 2-1. 팔을 움직이지 않고 계획 확인

팔이 블록을 가리지 않는 상태에서 실행한다. `--dry`는 HOME으로 이동시키지도 않는다.

```bash
python -m kitbot_exec.pick --color purple --dry --no-place
```

- `dry_ok`: 계산 성공. 실제 도달 정확도를 확인한 것은 아니다.
- 검출 흔들림 최대 1~2mm 이하는 초기 참고값이다. 크게 흔들리면 조명·검출부터 확인한다.
- 현재 코드는 `--no-place`여도 **내려가기·들어 올리기 경로까지 계산**한다. 그 구간의 실패를 “접근도 불가능”으로 해석하지 않는다. 실패 문장과 위치를 남기고, 우선 계획이 되는 작업 영역에서 평가한다.

### 2-2. 진단 기능을 이 터미널에 등록 — 이 블록 자체는 팔을 움직이지 않음

기존 `pick`에는 명령−실제 관절값 출력 옵션이 없다. 아래 함수는 실행할 때 같은 프로세스에서 진단 출력을 덧붙인다. **목표 관절값·보상량·제어 설정은 바꾸지 않는다.** 실제 이동은 기존 `pick --no-place --step`이 수행한다.

아래 블록 전체를 한 번 붙여 넣는다. 이후에는 짧은 `s02_eval ...` 또는 `s02_approach` 명령으로 실행한다.

```bash
s02_approach() {
    python -u -c '
import json
import os
from pathlib import Path
import numpy as np
from kitbot_exec import pick
from kitbot_exec.kinematics import ARM_JOINTS

original_measure = pick.measure_with_leader

def diagnose(arm, leader, kin, q_ref, axes, jaw_center_mm):
    q_read, gripper = arm.read()
    target_tip, _ = kin.fk(q_ref)
    read_tip, _ = kin.fk(q_read)
    target_xy = pick.jaw_center_xy(kin, q_ref, jaw_center_mm)
    read_xy = pick.jaw_center_xy(kin, q_read, jaw_center_mm)
    record = {
        "trial": os.environ.get("S02_TRIAL", "unnamed"),
        "joints": list(ARM_JOINTS),
        "target_deg": np.asarray(q_ref).tolist(),
        "read_deg": q_read.tolist(),
        "target_minus_read_deg": (np.asarray(q_ref) - q_read).tolist(),
        "target_minus_read_xy_model_mm": (target_xy - read_xy).tolist(),
        "target_minus_read_z_model_mm": float(target_tip[2] - read_tip[2]),
        "gripper_read": float(gripper),
    }
    print("\n[자동 접근 직후 / approach diagnostic]")
    print(json.dumps(record, ensure_ascii=False, indent=2))
    path = Path(os.environ["S02_RUN"]) / "approach_diagnostics.jsonl"
    with path.open("a", encoding="utf-8") as f:
        f.write(json.dumps({**record, "phase": "before_manual"}) + "\n")
    q_aligned = original_measure(arm, leader, kin, q_ref, axes, jaw_center_mm)
    if q_aligned is not None:
        aligned_xy = pick.jaw_center_xy(kin, q_aligned, jaw_center_mm)
        aligned_tip, _ = kin.fk(q_aligned)
        record["alignment_delta_xy_model_mm"] = (aligned_xy - read_xy).tolist()
        record["alignment_delta_z_model_mm"] = float(aligned_tip[2] - read_tip[2])
        record["alignment_delta_yaw_model_deg"] = float(pick.wrap90(
            kin._tool_yaw(q_aligned) - kin._tool_yaw(q_read)))
        print("\n[자동 접근에서 수동 정렬까지 / alignment diagnostic]")
        print(json.dumps(record, ensure_ascii=False, indent=2))
        with path.open("a", encoding="utf-8") as f:
            f.write(json.dumps({**record, "phase": "after_manual"}) + "\n")
    return q_aligned

pick.measure_with_leader = diagnose
pick.main()
' --color purple --no-place --step "$@"
}

# 평가 시작 시의 보정을 고정한다. 파일이 없으면 보정 없이 시작한다.
if [ ! -f var/approach_corrections.json ]; then
    printf '[]\n' > var/approach_corrections.json
fi
cp var/approach_corrections.json "$S02_RUN/eval_fixed.json"

s02_eval() {
    export S02_TRIAL="$1"
    shift
    cp "$S02_RUN/eval_fixed.json" var/approach_corrections.json || return
    s02_approach "$@" 2>&1 | tee "$S02_RUN/${S02_TRIAL}.txt"
    local s02_status=$?
    cp var/approach_corrections.json "$S02_RUN/${S02_TRIAL}_corrections.json"
    cp "$S02_RUN/eval_fixed.json" var/approach_corrections.json
    return "$s02_status"
}
```

`--no-place`에서 마지막 Enter를 누르면 보정 데이터가 한 건 추가된다. `s02_eval`은 **매번 같은 보정으로 시작하고, 추가된 기록은 시행별로 보관한 뒤 원래 보정을 복원**한다. 평가하면서 보정이 달라지는 것을 막기 위한 함수다. 시행 이름은 영문·숫자·밑줄로 매번 다르게 지정한다.

## 3. 가까이·중간·멀리 반복 접근 — 먼저 6회

각 위치를 테이프로 표시한다. 블록 각도는 우선 0°로 맞춘다. 같은 위치를 두 번씩 반복하되, **명령을 자동 반복 실행하지 않는다.** 각 시행 사이에 블록과 주변 상태를 확인한다.

```bash
# 가까운 곳 첫 시행. 아래 하나만 실행한 뒤 현장에서 확인한다.
s02_eval near_0_r1
```

다음 시행은 블록을 배치하고 이름만 바꿔 실행한다: `near_0_r2`, `middle_0_r1`, `middle_0_r2`, `far_0_r1`, `far_0_r2`.

### 한 시행에서 하는 일

1. Enter로 HOME 이동 → 검출·계획 → 블록 위 약 40mm 접근까지 진행한다.
2. `[approach diagnostic]` 출력 뒤 `[리더암 맞추기]`에서 멈춘다. **아직 리더암으로 팔로워를 움직이지 않는다.** 자동 접근 상태의 높이, 수평 어긋남, 각도, 흔들림을 관찰·촬영한다. 외부 자·기준선 측정이 가능하면 함께 기록한다.
3. 손목 영상에 목표가 보이는지도 확인한다. 아래 별도 터미널 명령은 팔을 제어하지 않고 **손목 카메라만** 사용한다. 먼저 환경과 작업 폴더를 맞춘 뒤 실행하고, `s`로 사진을 남긴 다음 `q`로 닫는다. `pick`이 사용하는 위 카메라는 동시에 열지 않는다.

   ```bash
   source ~/miniforge3/bin/activate lerobot
   cd ~/Desktop/SO_ARM101/project/src
   python -m kitbot_exec.view_blocks --role wrist --color purple
   ```

   손목 화면에서는 검출 개수보다 **실제 목표 블록이 보이는지·가려졌는지**를 본다. 위 카메라용 HSV·면적 기준이 손목 영상에 그대로 맞는다는 보장은 없다.

4. 원래 터미널에서 리더암을 팔로워 자세와 최대한 가깝게 맞춘다. 프로그램 허용값은 15°지만 이것은 정밀 인계 기준이 아니다. 벌림도 약 45mm로 맞춘 뒤 Enter를 누른다.
5. 수동 정렬은 **블록 윗면 위 약 40mm를 유지하며** 수평 위치와 손목 각도를 맞춘다. 현재 화면의 “1cm쯤” 안내 대신 이 문서의 높이를 따른다. 부리를 더 닫거나 높이를 내려 오차를 줄이지 않는다. 실물 높이를 우선 보고, 화면의 높이 변화도 참고한다. 자동 접근 높이가 이미 목표에서 벗어났다면 높이 이상으로 기록한다. 정렬 중 높이를 바꾼 시행은 같은 높이의 수평 오차 평가로 집계하지 않는다. 기울기는 가능하면 3° 안으로 맞추되, 도달이 안 되면 억지로 맞추지 말고 값을 기록한다.
6. 정렬했으면 Enter. `[alignment diagnostic]`과 기존 보정 출력이 나온다. 이후 HOME 복귀 단계에서도 Enter를 눌러 정상 종료한다. 정렬을 할 수 없으면 `x` + Enter로 취소하고, 실패 이유를 남긴다.

### 출력 해석

| 출력 | 의미와 한계 |
|---|---|
| `target_minus_read_deg` | 계획한 목표 관절값 − 접근 직후 읽은 관절값. 하위 드라이버의 제한 후 실제 전송값을 기록한 것은 아님 |
| `target_minus_read_xy_model_mm` | 위 관절 차이가 모델상 두 부리 가운데 위치에 미치는 수평 차이 |
| `alignment_delta_xy_model_mm` | 자동 접근 직후 읽은 자세 → 사람이 정렬한 자세 사이의 모델상 수평 이동량 |
| `alignment_delta_z_model_mm` | 수동 정렬 중 높이가 얼마나 달라졌는지 확인하는 보조값. 물리 높이도 함께 확인 |
| 기존 `이번 어긋남` | 수동 정렬 좌표와 보정된 목표 사이의 모델상 차이. 외부 기준으로 잰 실제 접근 오차와 동일시하지 않음 |

관절 차이가 1° 이상이라고 원인을 확정하지 않는다. 같은 위치에서 반복되는지, 거리와 함께 커지는지, 실물 어긋남 방향과 맞는지 함께 본다. FK로 계산한 mm는 모델이 틀리면 함께 틀릴 수 있다.

| 6회 결과 | 다음 행동 |
|---|---|
| 같은 위치에서 안정적으로 접근하고 잔여 오차가 작음 | 보정 추가 없이 5번 평가로 |
| 같은 위치에서는 반복되지만 위치마다 일정하게 치우침 | 4번에서 같은 높이로 보정 재수집 후 평가 |
| 같은 위치에서도 오차·흔들림·관절 차이가 크게 달라짐 | 로그를 남기고 구동·유격·카메라 흔들림 진단. 보정점을 늘려 평균으로 덮지 않음 |
| 관절 차이는 작지만 실물 위치가 일관되게 틀림 | 카메라 대응·끝점 기준·모델을 우선 점검. 이것만으로 원인 확정은 아님 |

보정 전후를 비교할 필요가 있으면 같은 위치에서 `s02_eval middle_0_no_corr --no-correction`을 실행한다. `--no-correction`은 보정 적용만 끄며 저장을 막지는 않는다. 반드시 `s02_eval`을 통해 실행한다.

## 4. 접근 보정 재수집 — 필요할 때만

카메라·모델·벌림 기준이 정해졌고, 같은 위치의 접근이 반복될 때 수행한다. 기존의 10mm 높이 정렬 기록과 새 40mm 높이 기록을 섞지 않는다.

```bash
cp var/approach_corrections.json "$S02_RUN/corrections_before_recollect.json"
printf '[]\n' > var/approach_corrections.json
```

작업 영역에 분산된 **8~12곳**에서 모은다. 가까이·멀리·좌우와 블록 회전 0°·30°를 섞는다. 한 줄에 몰린 점을 피하고, 5번에서 평가할 위치도 별도로 남겨 둔다.

```bash
# 첫 보정점. 다음 점은 collect02, collect03 ... 으로 이름을 바꾼다.
S02_TRIAL=collect01 s02_approach --no-correction 2>&1 | tee "$S02_RUN/collect01.txt"
```

- **수집에는 `s02_eval`을 쓰지 않는다.** 수집된 보정 기록이 누적되어야 한다.
- `--no-correction`으로 수집 중 접근 조건을 일정하게 유지한다. 수동 정렬·Enter로 새 기록은 저장된다. 보정 없는 접근 자체가 작업 범위를 벗어나면 진행하지 않는다.
- 3번과 똑같이 실제 높이 약 40mm·벌림 45mm를 유지한다. 원래 프로그램의 “1cm 위” 안내는 따르지 않는다.
- 6건부터 기존 코드가 x, y 위치별 1차식을 사용한다. 기록 수가 많다는 이유만으로 보정이 좋아졌다고 판단하지 않는다.
- 명백한 측정 실수는 확정 전에 `x`로 취소하고 사유를 기록한다. 저장 후 잘못된 기록을 발견하면 원본을 보존하고 해당 시행을 표시한다. 큰 오차를 없애기 위해 임의로 기록을 골라 지우지 않는다.

수집을 마치면 보정 상태를 확인하고 새 평가 기준으로 고정한다.

## 5. 별도 위치에서 고정 평가 — 9곳 × 각도 2종

보정 수집 위치와 다른 위치를 작업 영역 안에 3×3으로 정한다. 각 위치에서 0°·30°를 시험한다. 3번의 절차로 측정하며, 모든 시행은 `s02_eval`을 사용한다.

```bash
# 격자 첫 위치, 각도 0°. 이후 블록을 바꾸고 시행 이름을 바꾼다.
s02_eval grid01_0
```

시행 이름: `grid01_0`, `grid01_30`, …, `grid09_0`, `grid09_30`. 계획 실패·취소·목표 가림도 분모에서 빼지 않고 별도로 집계한다. 이 위치를 보고 보정식을 다시 맞추면 더 이상 별도 평가가 아니므로 새 평가 위치가 필요하다.

평가 시작 전에 아래 기록표를 만든다. 손목 사진은 `var/frames/`에 저장되므로 시행과 사진 파일명을 연결해 적는다.

```bash
printf '%s\n' 'trial,physical_height_mm,physical_xy_error_mm,physical_yaw_error_deg,target_visible,stable,frame_file,notes' > "$S02_RUN/observations.csv"
```

각 시행 뒤 파일에 한 줄씩 적는다. 실측하지 못한 수치는 빈칸으로 남기고 `notes`에 미측정이라고 적는다. 모델에서 계산한 mm를 실측 칸에 옮기지 않는다.

### 내일 판정할 것

- **기존 S02 참고 지표:** 실측 수평 오차 10mm 이내·각도 10° 이내인 비율을 보고한다. 두 조건을 함께 만족하는 시도 90% 이상을 기존 기준과 비교하되, 측정법과 미측정 건수를 함께 적는다. 모델 보조값만 있으면 실측 통과라고 기록하지 않는다.
- **ACT 인계 준비:** 접근 후 목표가 손목 영상에 보이고, 높이·벌림·자세가 반복되며, 심한 흔들림 없이 사람이 그 상태에서 이어서 집을 수 있는 작업 범위를 정한다. 이것은 ACT 성공을 입증하는 단계가 아니다.
- **10mm를 넘는 경우:** 오차가 일정하고 영상으로 목표를 확인할 수 있는지 기록해 ACT 시연에서 다룰 후보 범위를 정한다. ACT가 반드시 보정한다고 가정하지 않는다. 시야 밖·도달 불가·불안정 상태는 먼저 접근 단계에서 해결한다.

### 선택: 계산 방식으로 집기→바구니→HOME 한 번 확인

접근과 실제 내려갈 경로를 확인했고, HOME·BASKET 자세가 현재 배치에 맞을 때만 한다. 이것은 ACT와 비교할 계산 방식의 기준 동작이다.

```bash
python -m kitbot_exec.pick --color purple --step
```

들어 올린 뒤 실제로 블록을 잡았는지, 바구니 테두리를 피하는지, 블록이 안에 남았는지, HOME으로 돌아왔는지 눈으로 확인한다. `placed` 로그는 놓기 명령을 수행했다는 뜻이며 바구니 투입 성공을 확인한 결과가 아니다. BASKET은 모델 z 숫자만 보지 말고 테두리와 매달린 블록의 실제 여유를 확인한다.

## 중단·복구

- 정상 취소: 리더암 맞추기 또는 정렬 단계에서 `x` + Enter. 이후 HOME 복귀 단계의 Enter까지 진행한다.
- Ctrl+C: HOME 복귀를 보장하지 않는다. 팔은 마지막 자세에서 힘을 유지한다. 중단 자세에서 자동 HOME 명령을 다시 보내기 전에 경로를 확인한다.
- 손으로 팔을 움직여야 할 때: 팔을 받친 상태에서 아래 명령을 실행한다.

