## 1. 데이터에서 보이는 것 (계산)
기록 5건의 어긋남(실제로 맞춘 위치 − 카메라 계산 위치)을 팔 받침대 기준 방향으로 나눴다.

| 받침대에서 거리 | 바깥 방향 어긋남 | 옆 방향 어긋남 |
|---|---|---|
| 160mm | 3.2mm | 1.6mm |
| 170mm | 8.2mm | 8.6mm |
| 184mm | 4.6mm | 1.0mm |
| 187mm | 7.8mm | 3.1mm |
| 228mm | 13.7mm | 1.1mm |

- 어긋남이 거의 모두 **바깥 방향**이고 **멀수록 커진다** → 팔이 목표까지 덜 뻗는다.
- 평균 dx +3.6, dy +7.5mm, 표준편차 2.4 / 3.5mm, 각도 평균 −1.8°.

## 2. 원인 후보 (의심 순서)

| 순위 | 원인 | 왜 의심하나 | 확인 방법 |
|---|---|---|---|
| 1 | **서보가 명령보다 덜 가서 멈추는데, 그 차이가 보정 기록에 안 들어감** | 이동 완료 기준이 "명령과 2° 안"이고 2초 지나면 덜 가도 끝낸다(`arm.py` `_settle`). 어깨 2°는 200mm 거리에서 약 7mm(계산). 보정 기록은 팔로워 **실제 관절값**(`arm.read()`)으로 위치를 계산하지만, 실행 때 역기구학 결과는 **명령값**으로 보낸다 → 다음 실행에서도 같은 만큼 덜 간다. 기록을 몇 건 모아도 이 차이는 남는다. 멀수록 중력 부담이 커서 덜 가는 양이 커지는 것과 위 표가 맞다 | 실험 A |
| 2 | 팔 모델의 관절 0점 어긋남 | 블록 윗면 높이가 25mm가 아니라 약 3mm로 계산된다(22mm 불일치). LeRobot의 0° = 캘리브레이션 가동 범위 가운데이고, 설계 파일(URDF)의 0°와 몇 도 다르면 높이 오차와 함께 거리에 비례하는 바깥 방향 오차가 생긴다. 보정(블록 윗면에 닿음)·접근(30~50mm)·리더암 측정(약 1cm)의 높이가 달라 서로 상쇄되지 않는다 | 실험 C |
| 3 | 평균 하나로만 보정 | 거리에 따라 커지는 오차를 평균으로 빼면 가까운 곳은 과보정, 먼 곳은 부족. 위치별 식은 6건 이상부터인데 기록을 5건으로 줄이면서 꺼짐 | 실험 D |
| 4 | 렌즈 왜곡 미보정 | 평면 대응 변환은 렌즈 휘어짐을 표현 못 한다. 화면 → 로봇 보정의 한 점 빼고 오차 평균 6.0 / 최대 11.1mm(가장자리). 다만 이 오차는 받침대가 아니라 화면 중심 기준으로 퍼져 1·2보다 덜 유력 | 실험 F |
| 5 | 측정 방법 오차 | 블록 1cm 위에서 눈으로 맞춤, 그리퍼 기울기 10°까지 허용. 기울기 10°에서 높이 차이 30mm면 약 5mm(계산) | 측정할 때 기울기 표시를 3° 안으로 맞춘다 |

## 3. 내일 아침 실행 순서

**시작 전 (5분, 매번 필수)**
- `python -m kitbot_exec.camera_lock apply` (재부팅·USB 재연결 시 카메라 설정 초기화됨)
- 카메라 장대가 어제와 같은 자리인지 확인. 움직였으면 화면 → 로봇 보정(collect_calib)부터 다시 한다.

| 순서 | 실험 | 시간 | 방법 | 판단 |
|---|---|---|---|---|
| A | **명령값 vs 실제 관절값 차이 재기** | 10분 | 블록을 가까운 곳~먼 곳 5곳에 두고 `pick --no-place --step`으로 접근. 멈춘 뒤 관절별 (명령 − 실제)와, 그 차이로 생기는 그리퍼 끝 위치 차이(mm)를 출력 | 어깨·팔꿈치 차이 1° 이상이고 먼 곳일수록 크면 원인 1 확정 → B. 차이가 작으면 B 건너뛰고 C |
| B | **원인 1 수정 후 재확인** | 20분 | 아래 "필요한 코드 변경" 1·2 적용 후 A와 같은 5곳에서 다시 접근 | 5곳 접근 오차가 줄면 수정 효과 확인 |
| C | **팔 모델을 자로 확인** | 20분 | 자세 3개(가까이·멀리·옆)에서 계산한 그리퍼 끝 위치와 자로 잰 위치 비교 (S02-4에서 미뤄 둔 확인) | 높이·거리 차이가 5mm 넘게 일정하면 관절 0점 보정값을 찾아 넣는다 |
| D | **접근 보정 기록 새로 모으기** | 30분 | 기존 `var/approach_corrections.json`은 백업 후 지움. 가까운 곳~먼 곳 8건 이상, 하나도 빼지 않음 → 위치별 식 보정 | A~C로 원인을 고친 뒤에만 의미가 있다(어제는 이 순서가 거꾸로였음) |
| E | **판정 실험** | 40분 | 9곳 × 블록 각도 2종 이상 접근 오차 측정 (S02 판정 기준 1) | 10mm 안 90% 이상 + 각도 10° 이하 → 집기는 계산으로. 아니면 ACT가 손목 카메라로 마지막 위치를 맞추는 쪽 |
| F | (필요할 때만) 렌즈 왜곡 보정 | 30분 | 체커보드 촬영 → 왜곡 보정 후 화면 → 로봇 보정 재수집 | E에서 화면 가장자리만 틀릴 때 |

- 오전 목표: E(판정 실험)까지.
- 실행 결과는 S02.md 검증 이력에 숫자로 남긴다. `var/pick_log.jsonl`에서 필요한 줄은 `project/evidence/`에 복사해 둔다.

## 4. 필요한 코드 변경 (구현 전)

| # | 파일 | 변경 | 이유 |
|---|---|---|---|
| 1 | `kitbot_exec/arm.py` `_settle` | 멈춤 기준 2° → 0.5°(값은 실험 A 결과로 조정). 기준 안에 못 들어오면 "읽은 값과의 차이만큼 명령을 더 준다"(명령 = 목표 + (목표 − 실제))를 2~3번 반복. 최대 보상량을 제한(예: 3°)해 팔이 튀지 않게 | 서보가 덜 가는 만큼을 실행 단계에서 메움 |
| 2 | `kitbot_exec/pick.py` `measure_with_leader`·기록 부분 | 보정 기록 위치를 실제 관절값(`arm.read()`) 대신 **그 순간 팔로워에 보낸 명령값(리더암 값)** 으로도 계산해 둘 다 저장 (`measured_cmd`, `measured_read`) | 실행 때 쓰는 값(명령)과 같은 기준으로 보정해야 바이어스가 사라짐. 둘 다 남겨 어느 쪽이 맞는지 비교 |
| 3 | `kitbot_exec/pick.py` 접근 직후 | 접근 자세에서 관절별 (명령 − 실제)와 그로 인한 그리퍼 끝 위치 차이(mm)를 출력하고 로그에 저장 | 실험 A 진단용. 이후에도 매 실행 확인 |
| 4 | `kitbot_exec/correction.py` | 위치별 식을 x, y 대신 "받침대에서 거리" 기준으로도 맞출 수 있게(바깥 방향 오차 = a + b × 거리) | 기록이 적어도(4건 이상) 거리 비례 오차를 잡을 수 있음 |

- 변경 후 기존 시험(lerobot 환경 60개)을 다시 돌리고, 1·3은 가짜 팔로 "덜 가는 팔"을 흉내 내는 시험을 추가한다.
