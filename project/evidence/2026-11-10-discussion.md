## 사용자 분해안과 Step 구성
사용자 분해안
1. 비전 + 4축 IK로 색과 무관하게 블록 위 30~50mm 지점으로 이동
2. 색 2개 구분 → N개 구분
3. 색은 맞다고 믿고, 블록 회전을 바꿔 가며 ACT 학습

| Step | 목표 | 꼭 실물로 확인할 것 (실패하면 방향이 바뀌는 가정) | Step 안의 작은 확인 |
|---|---|---|---|
| S02 | 비전 + IK로 색과 무관하게 블록 위로 이동하고 손목 각도 맞추기 (분해안 1) | 그리퍼가 실제로 몇 mm, 몇 도 어긋나나 → 하이브리드로 갈지 정하는 갈림길 | 장비 연결, 카메라 고정·노출 고정, 깊이로 블록 검출, 팔 기구학 확인, 카메라-로봇 보정 |
| S03 | 색 판별 2색 → N색 (분해안 2, S02와 병행 가능) | 실제 블록 8색 중 어떤 색끼리 섞이나 | 조명 변화 |
| S04 | 학습 없이 집기 → 놓기 → 확인 → 재시도 한 바퀴 (ACT를 끼울 자리) | 서보 신호로 빈손을 맞히나, 실패 시 홈 복귀·재시도가 실제로 도나 | 키트 칸 위치, Pi 주문 → 노트북 실행 연결, 학습 없는 집기 성공률(ACT와 비교할 기준) |
| S05 | ACT 학습 (분해안 3) | 처음 보는 위치·각도에서 성공률, 추론 지연 | 자동 접근 직후 리더암으로 이어받기, 6GB 학습 시간·메모리, 시연 수별 성공률 |
| S06 | 최종 평가 (+ 옵션 신뢰성 기능) | 처음 보는 위치 80% 이상, 실패 감지·재시도 | 블록 하나 담는 시간 |

- 사용자 진행 방식(profile.md 4번): 실물 검증은 Sim2Real 관점. 설계상 될 것 같은 것을 믿지 말고 현실에서 확인하되, AI가 세운 가정을 전부 하나씩 실험하지는 않는다.
- S04를 넣은 이유: ACT 전에 전체가 학습 없이 한 바퀴 돌면, ACT는 "집기" 한 부분만 갈아 끼우는 부품이 된다. ACT가 잘 안 될 때 원인을 ACT로 좁힐 수 있다.
- S05에서 실제로 막힐 가능성이 큰 지점: 자동 접근이 끝난 뒤 사람이 리더암으로 이어받을 때, 리더암과 팔로워암의 자세가 달라 팔로워암이 순간적으로 튈 수 있다.

## 블록 회전은 CV + 손목 회전 관절로 (제안, 사용자 이의 없음)
| 비교 | CV가 회전을 맞춤 | ACT가 회전까지 학습 |
|---|---|---|
| 계산 | 위에서 본 블록 윤곽의 기울기로 각도를 구해 손목 회전 관절에 넣음 | 정책이 영상에서 스스로 알아내야 함 |
| 필요한 시연 수 | 위치만 다양하면 됨 | 위치 × 회전 조합을 다 덮어야 해서 곱으로 늘어남 |
| 처음 보는 각도 | 계산이라 어느 각도든 같게 동작 | 시연에 없던 각도에서 무너지기 쉬움 |
| 실패 원인 찾기 | 각도 오차를 "몇 도"로 측정 가능 | 블랙박스 |
- 정육면체는 90°마다 같은 모양 → 손목은 ±45° 범위 안에서만 돌리면 된다.
- 회전은 역기구학 문제가 아니다. 4축(어깨 회전·어깨·팔꿈치·손목 굽힘)이 위치와 그리퍼 기울기를, 손목 회전 관절 하나가 블록 각도를 맡는다.
- 시연할 때 블록 회전은 여전히 바꿔 가며 녹화한다. CV가 맞추고 남은 몇 도의 오차를 ACT가 보정하게 하기 위해서다.
- 주의: 비스듬한 카메라에서는 이미지 위 각도가 왜곡된다 → 테이블 평면 좌표로 옮긴 뒤 각도를 계산한다.

## 위에서 보는 카메라: RealSense vs 웹캠 (모델 확인 후 결정, 보류)
| 역할 | RealSense (깊이 있음) | 웹캠 (깊이 없음) |
|---|---|---|
| 색과 무관하게 블록 찾기 | 테이블보다 높은 것 = 블록. 색·그림자와 무관 | 빈 테이블 사진과 비교해 차이를 찾아야 함. 그림자·조명 변화에 약함 |
| 블록 위치 | 깊이로 바로 3D 위치 | 테이블 평면 보정을 따로 해야 함 |
| 들어 올렸는지 확인 | 높이로 판정 | 원래 자리가 비었는지만 볼 수 있음 |
| 붙어 있는 블록 나누기 | 깊이 경계로 가능 | 같은 색끼리 붙으면 어려움 |
- 카메라를 팔의 움직이는 부분에 달면 시점이 바뀌어 위치 보정이 깨진다. 팔 받침대처럼 고정된 곳은 괜찮다.
- 예외: RealSense가 근거리용 D405라면 "위 = 웹캠, 손목 = D405"도 타당하다. D435 계열은 가까운 거리를 못 재고 손목에 달기 무겁다.
- 현재 가정: 위 = RealSense, 손목 = 웹캠 1, 전체·키트 = 웹캠 2. 모델 확인 후 다시 판단.

## "기록한 동작 재생"과 ACT의 차이 (사용자 질문에 대한 설명)
- 기록한 동작 재생: 팔이 지나갈 관절 각도 몇 개를 미리 저장해 두고, 매번 그 순서대로 똑같이 움직이는 방식. 카메라도 신경망도 쓰지 않는다(매크로와 같음).
- 예: 키트 3번 칸에 놓기 = [키트 위 지나가는 점] → [3번 칸 위 3cm] → [그리퍼 열기] → [홈]의 관절값 목록을 부드럽게 이어 가며 움직임.

| 비교 | 기록한 동작 재생 | ACT |
|---|---|---|
| 관절값을 정하는 것 | 미리 저장한 목록 | 신경망이 1초에 30번 정도 새로 계산 |
| 보는 것 | 아무것도 안 봄 | 카메라 영상 + 현재 관절값 |
| 매번 같은가 | 항상 똑같이 움직임 | 보이는 상황에 따라 달라짐 |
| 준비물 | 자세 몇 개 저장 | 사람의 시연 수십~수백 번 + 학습 |
| 잘하는 일 | 위치가 고정된 일 (키트 박스, 홈) | 위치·각도가 매번 다른 일 (블록 집기) |
| 못하는 일 | 대상이 움직이면 대응 못 함 | 시연에 없던 상황, 왜 실패했는지 알기 어려움 |

- 블록 하나를 담는 전체 순서: **계산으로 블록 위 접근** → **ACT로 집고 들어 올리기** → (잡았는지 확인. 빈손이면 홈으로 돌아가 다시) → **키트에 놓기**

## Diffusion으로 바꾸면 나아지나 (사용자 질문, 답변 채택)
- 결론: 모델만 바꿔서는 크게 나아지지 않는다. 지난 ACT의 한계("정해진 반복 작업만")는 주로 시연 데이터의 분포에서 왔고, Diffusion도 시연에 없던 위치에서는 똑같이 무너진다.

| 비교 | ACT | Diffusion Policy |
|---|---|---|
| 처음 보는 위치 | 시연 분포에 달림 | 시연 분포에 달림 (같음) |
| 정답 동작이 여러 개인 상황 | 평균을 내 어중간하게 움직이기 쉬움 | 강함. 핵심 장점 |
| 동작의 부드러움 | 보통 | 좋은 편 |
| 추론 속도 | 빠름 | 계산을 여러 번 반복해 느림 (4050에서 수십~수백 ms, 추정) |
| 학습 시간 | 짧은 편 | 긴 편 |

- "정답 동작이 여러 개인 상황" 예: 빨강 블록이 두 개면 사람은 시연 때 왼쪽도 집고 오른쪽도 집는다. ACT는 둘을 평균 내 가운데로 갈 수 있고, Diffusion은 하나를 골라 간다.
  - AI가 블록 바로 위에서 집기만 할 때(1단계): 이런 상황이 거의 없다 → Diffusion 장점이 작다.
  - AI가 홈에서부터 접근할 때(2단계, 보류): 이런 상황이 많다 → Diffusion 장점이 커진다.
- 그래서 Diffusion 비교는 2단계를 다시 검토할 때 함께 다룬다.

## AI 범위를 단계적으로 넓히는 구조 (1단계 진행, 2·3단계 보류)
| 단계 | AI가 맡는 것 | 고전 방법이 맡는 것 |
|---|---|---|
| 1단계 (진행) | 집고 들어 올리기 | 인식, 접근, 놓기, 확인 |
| 2단계 (보류) | 홈에서 접근 + 집기 (ACT와 Diffusion 비교) | 인식, 놓기, 확인 |
| 3단계 (선택, 보류) | 놓기, 잡았는지 판정(학습형 분류기), 블록 인식(학습형 검출 모델) | 안전 제한, 기준선 |
- 단계마다 "AI가 고전 방법보다 나은가"를 같은 시험 위치에서 숫자로 비교한다.
- 고전 방법은 끝까지 쓴다: AI와 비교할 기준선, 안전 제한(테이블 아래로 내려가지 않게), 실패 판정(홈 복귀·재시도의 출발점), 학습 데이터 자동 기록(시연할 때 인식 결과로 목표 위치 저장).

## 놓기: 키트를 벗어날 위험과 대응 (사용자 질문, 답변 채택)
- 놓기가 시작될 때 블록은 이미 그리퍼 안에 있다. 블록의 처음 위치는 놓기에 영향을 주지 않는다.
- 실제 위험 두 가지

| 위험 | 무슨 일이 생기나 | 대응 |
|---|---|---|
| 블록이 그리퍼 안에서 치우쳐 잡힘 | 치우친 만큼 칸에서 벗어나 놓임. 허용 범위 ≈ (칸 폭 − 블록 한 변) ÷ 2 | 그리퍼가 닫히는 방향으로는 블록이 저절로 가운데로 모인다. 다른 방향 치우침은 놓기 직전 웹캠으로 재서 놓을 위치를 보정 |
| 키트 박스가 움직임 | 저장한 관절값이 틀린 곳을 가리킴 | 관절값을 고정 저장하지 않는다. 키트 박스에 붙인 표식(ArUco 같은 인쇄 마커)을 카메라로 찾아 칸 좌표를 계산하고 역기구학으로 놓는다 |

- 놓은 뒤 웹캠으로 블록이 칸 안에 있는지 확인한다.
- 그래서 놓기는 "매크로 재생"이 아니라 "카메라로 칸 위치를 보고 계산해서 놓기"가 된다. 그래도 치우침이 커서 부족하면 놓기를 AI에게 맡긴다(3단계).
- 전날 기록의 "칸별 놓기 자세를 미리 기록해 재생"은 이 방식으로 바뀐다.
